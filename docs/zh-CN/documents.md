# 文档写作

[首页](../../README.zh-CN.md) · [文档导航](README.md) · [English](../documents.md)

`documents` 工具组用来逐节写 Markdown 文档、处理审阅评论，并导出 Word、PDF 或 HTML。文档本身始终是普通的 `.md` 文件，Astra 写作期间你也可以用任何编辑器打开和修改。

[文档格式](#文档格式) · [工具](#工具) · [安全修改](#安全修改) · [审阅评论](#审阅评论) · [导出](#导出) · [桌面版预览](#桌面版预览) · [终端查看](#终端查看) · [限制](#限制)

## 文档格式

```markdown
# 项目提案

一段话说清楚主要结论。

<!-- astra:section id="background" -->
## 1 背景

已写好的正文……

<!-- astra:section id="data" status="pending" intent="参与者、流程、标签" -->
## 2 数据采集

*Pending: 参与者、流程、标签*
```

- 第一个一级标题是文档标题，它下面的文字是导语（节 id 为 `_lead`）。
- 其他每个 `#` 标题开始一节，到下一个同级或更高级标题为止，所以二级节包含它下面的三级小节。写入一节只替换它自己的正文（到第一个小节为止），删除一节则连同小节一起删除。
- 标题上方的 HTML 注释让节 id 在改标题后保持不变。你自己加的、没有注释的标题，id 由标题文字生成。
- 还没写的节显示一行可见的 `*Pending: …*`。
- 标记和评论在渲染后的 Markdown 里看不见。代码块里的内容不会被当成标题、标记或评论。

## 工具

在默认的稳定工具清单下（`PROMPT_CACHE_STABLE_TOOLS=1`），这四个工具始终提供给模型。改用渐进式路由时，请求涉及文档、报告、提案、论文或导出，Astra 才激活这个工具组，也可以按需激活。

| 工具 | 作用 |
| --- | --- |
| `doc_create` | 新建文档：标题、导语、每节一个待写占位 |
| `doc_outline` | 列出各节的 id、级别、状态、字数和哈希，以及待处理的审阅评论；可附带某一节的原文 |
| `doc_edit` | `write` 替换一节自己的正文（可顺便改标题，小节不动），`add` 在某节前后或文末插入新节，`remove` 删除一节及其小节，`resolve_comment` 删除已处理的评论并记录说明 |
| `doc_export` | 导出 Word、PDF 或 HTML |

早先按操作拆分的工具（`doc_write_section`、`doc_add_section`、`doc_remove_section`、`doc_comments`、`doc_resolve_comment`）仍可执行，用于旧会话记录，但不再提供给模型。

## 安全修改

- 填写未改动过的待写节，不需要额外参数。
- 改写已写好的节，或删除自身正文或小节已写好的节，需要最新大纲里的 `expected_hash`。hash 覆盖小节，所以改过小节后，上一级节的 hash 也会变。如果你在此期间改过那一节，调用会以 `section_changed` 失败，你的文字保留不动，Astra 会重读后再改。
- 每次写入都是原子替换；准备修改期间文件如果被改过，Astra 会拒绝写入。
- 写入会建立文件检查点，`checkpoint_restore` 和本轮改动记录都和文件工具一样可用。
- 路径遵循和文件工具相同的[文件系统策略](../execution.md)：工作区可写，其他位置需要审批。

## 审阅评论

在文档任意位置用 HTML 注释写修改意见：

```markdown
试点包括三个人。<!-- @astra: 写清楚是哪三个人 -->
```

然后让 Astra 处理评论。它会从 `doc_outline` 读出评论，修改相关的节，再用 `doc_edit` 逐条标记为已处理。需要你来决定的评论会保留，并附上说明。

## 导出

`doc_export` 默认把导出文件放在文档旁边，也可以指定输出路径。节标记和评论不会出现在导出文件里。待写占位会保留，并在结果里给出警告。

| 格式 | 引擎 |
| --- | --- |
| Word（`docx`） | 装了 pandoc 就用 pandoc，否则用内置的 python-docx 导出器 |
| PDF | 由 LibreOffice 把 Word 文件转换而成 |
| HTML | 装了 pandoc 就用 pandoc，否则用 markdown-it-py |

内置导出器需要先安装一次：

```text
astra setup --extra documents
```

在开发用的源码仓库里，`uv sync --inexact --extra documents` 效果相同。pandoc 是可选的。pandoc 或 LibreOffice 不在 `PATH` 上时，设置 `ASTRA_PANDOC` 或 `ASTRA_SOFFICE`。`engine` 参数（`auto`、`python-docx`、`pandoc`）可以手动指定引擎。

内置 Word 导出器支持：

- 标题（唯一的一级标题会用 Word 的"标题"样式）、段落、粗体、斜体、删除线、行内代码；
- 链接，以及无序、有序、嵌套和任务列表（任务项用 ☐ 或 ☒ 代替项目符号）；
- 带对齐的表格、代码块、引用、分隔线；
- PNG、JPEG、GIF、BMP、TIFF 和 WebP 图片。

在 macOS 上，无界面运行的 LibreOffice 可能读不到系统字体。所以转换 PDF 时，Astra 会把系统字体链接进它的临时配置，并替换本机没有的 Office 字体：Aptos 换成 Helvetica Neue，Consolas 换成 Menlo。正文含中日韩文字时，还会在临时的 Word 副本里给全部正文指定同一款本机已安装的中日韩字体（优先冬青黑体 Hiragino Sans GB），西文字母和数字也用它；样式里明确指定的字体（比如代码字体）不变。导出的 Word 文件本身不受影响。

用 `template` 传入一个 `.docx`，可以沿用其中的样式，比如课程或公司模板。不传模板时，两种引擎都用 A4 纸（`paper` 可改成 Letter）和 25 毫米页边距，表格占满正文宽度并带网格线。文档以唯一的一级标题开头时，pandoc 也会把这个标题设成 Word 的"标题"样式，其余标题各升一级。

图片必须是允许范围内的本地文件。远程图片不会下载，SVG 在 Word 里不支持，这两种都会换成替代文字并给出警告。内置导出器不转换原始 HTML、脚注和公式；pandoc 支持的 Markdown 更多。

## 桌面版预览

在[桌面版](../gui.md)里，**文件**面板会打开 Astra 正在写的文档，每次文档工具返回结果后自动刷新。

- 预览会渲染 Markdown 及其中的图片，并在正文上方列出待处理的评论。
- 点**源码**可以查看原始文本。
- 关闭面板、切换标签或点**← 返回**后，这个会话里不再自动跟随文档。

## 终端查看

在终端界面里，每个文档工具结果在对话中只占一行，例如 `文档 report.md · 写入「结果」 · 1 节待写 · /doc 12 查看`。活动栏里这些工具显示为 `DOC NEW`、`DOC WRITE`、`DOC EXPORT` 等。

| 命令 | 作用 |
| --- | --- |
| `/doc` | 在详情视图中打开最近的文档 |
| `/doc <编号>` | 打开某个工具结果对应的文档 |
| `/doc open [编号]` | 用系统默认程序打开文档 |

详情视图读取的是文件当前的内容：隐藏节标记，突出显示标题、审阅评论和待写的节，表格按显示宽度对齐。视图开着时，同一文档再有写入会自动跟着更新。**Ctrl+O** 仍然打开最近一次工具结果；如果最后运行的是别的工具，用 `/doc`。

## 限制

- 只有 `#` 标题会生成节，下划线式（setext）标题不会。
- 文档工具最多处理 2 MB 的文件。
- 这不是实时多人编辑器。分享时请发送导出的文件，或者把 Markdown 文件放在你自己同步的文件夹里。
