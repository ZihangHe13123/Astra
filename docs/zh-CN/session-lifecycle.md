# 防误停、受控重启与会话内唤醒

[English](../session-lifecycle.md) · **简体中文**

## 防止误停当前运行环境

本地执行工具会在启动命令前检查常见的 `kill`、`pkill`、`killall`、
`taskkill`、`Stop-Process`，以及目标为字面量的 Python `os.kill`、
`os.killpg`。当目标指向当前后端、核实过身份的 TUI/launcher 父进程，
或当前安装所拥有的服务时，会拒绝执行。工具审批和 YOLO 不能覆盖此检查。
无关进程的正常清理仍可执行，工具自身的子进程清理由现有进程管理器负责。

这是防误操作检查，不是任意代码的安全隔离。间接脚本、动态拼接的命令和
无法识别的进程身份可能不在检查范围内。Windows 宿主进程号不会拿来匹配
WSL 的 Linux 进程号；可识别的 Windows 互操作命令仍检查宿主目标。

## 受控重启

在本地 Work 会话输入 `/restart`。Astra 等当前回复、工具执行和保存结束，
再等待 TUI 确认接收结果，随后退出后端并用同一会话启动新后端。
`/restart cancel` 取消等待。等待超过 120 秒会取消重启，不会强行中断工作。
如果 TUI 无法完整显示某条更新，会取消重启并提示检查诊断记录。

重启等待期间暂停接收新工作和会话、连接变更，仍可响应审批和取消操作。
Agent 也可调用 `request_restart`，但须经过你的明确确认，YOLO 下也一样。
此操作不会更新依赖、重新加载 TUI 程序包或重启其他服务；后端崩溃不会自动重启。

## 当前会话里稍后继续

可以说：“每五分钟检查一下这个 CI，没有变化就安静，结束后告诉我并停止。”
Astra 可用 `schedule_wakeup` 创建计划，记录当前会话、原始请求、检查内容、
下次时间和过期时间。计划不会增加任何工具权限。

也可以直接输入：

```text
/wakeup after 300 检查一次本会话里的 CI 链接
/wakeup every 300 检查本会话里的 CI 链接，成功或失败后停止
/wakeup
/wakeup cancel
```

每个后端只保留一个计划，新计划会替换旧计划。延迟和重复间隔至少 60 秒，
默认一小时过期。工具可指定最长 12 小时的有效期，须晚于首次检查时间；
直接命令使用一小时的默认有效期。

当前正在工作时，到期检查等空闲后再执行，不累计错过的次数。每次检查仍走
原有 Agent 和工具权限，最多十轮、五分钟；原有回合预算或计划剩余时间更短时
取较短值。检查期间你发来新请求，会取消这次检查及其重复计划，再处理你的工作。
取消、替换后，旧检查迟到的结果会被丢弃。

检查通过 `report_wakeup` 报告结果：`unchanged` 静默，`changed` 展示有用变化，
`completed` 或 `failed` 展示结果并停止。执行失败或没有报告结果也会停止重复。
内部检查保留在会话存储中供核查，不会恢复成用户发言或无变化时的聊天输出；
有用的通知会保留在可见历史中。

切换会话、关闭 Astra、重启后端都会停止计划；重新打开不会补跑。
第一版仅支持本地 Work TUI，不支持 Bar、Minimal、本地 隔离模式或远程频道。

## 后台工作结束时

在 Work 会话里，Astra 留在后台的工作结束时会通知它，它会接着做，不用你再开口。
包括用 `background=true` 启动、或超过 `foreground_yield_ms` 仍在运行的命令，
写成命令的等待（例如 `until curl -fs http://localhost:3000; do sleep 2; done`），
以及后台子 agent 和团队成员。

- Astra 还在工作时，结束的结果会在它下一步之前送到。
- 它已经答完时，后端会为它新开一轮：对话里显示“后台任务完成，继续处理：…”，
  Astra 随后汇报结果。一秒内相继结束的工作合成一轮。
- Astra 已经通过 `process_poll`、`process_read`、`process_list` 或 `process_cancel`
  看到结束状态的命令，不会再通知一次。
- 子 agent 在后台运行时，Astra 会先回答你，不再停下来等它们，你可以在它们干活时
  继续和 Astra 对话。子 agent 的报告和发给 Astra 的消息一到，就会开启新的一轮。
  Astra 主动要等时（带 `wait_ms` 的 `delegate_poll`、`team_wait`）仍会等待。
  同一会话后面的回合可以查看、读取、取消前面回合派出的子 agent；团队成员通过所在团队操作。

正在回复、有问题等你回答、重启进行中、处于 Bar/Minimal/本地模式或远程频道时，
不会自动开启新的一轮；结束的工作会等到可以开启时再送达，其他会话里结束的工作等你切回那个会话时送达。这样的一轮里你发来的消息，
和普通回合一样作为插话处理。连续自动开启八轮、期间你没有发消息时
（`ASTRA_BACKGROUND_WAKE_LIMIT`），结果改为等你下一条消息时再交给 Astra，对话里会说明。
你停止某一轮后，那一轮启动的命令结束时不会再自动开启新的一轮，结果在你下一条消息时送达。
这些通知不增加任何权限。

这一功能只在运行中的后端里有效：重启 Astra 不会补发错过的结果；重启前留下的子 agent
报告会随你的下一条消息送达。使用本机模型时，Astra 和子 agent 共用该模型的请求名额
（`LLM_MAX_CONCURRENT_REQUESTS`，默认 1），因此回复可能要等子 agent 的请求完成。
