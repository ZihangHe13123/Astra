# 持久提醒与定时检查

`astra jobs` 保存定时任务、每次执行的记录和本地送达回执。GUI/TUI 使用
`/jobs` 管理同一份任务，不会改动当前对话或上下文缓存。它与关闭 Astra 就
取消的 `/wakeup` 相互独立。

```sh
astra jobs add 休息 --after 600 --reminder --prompt "起来活动一下"
astra jobs add 项目检查 --every 3600 --workdir /path/to/project \
  --prompt "只读检查项目状态，总结需要处理的事项" \
  --request "每小时检查这个项目，把结果留在本地收件箱"
astra jobs add rust-news --time 08:00 --days mon,tue,wed,thu,fri --web --notify on_change \
  --prompt "看看有没有新的 Rust 2026 edition 讨论" \
  --request "工作日每天早上告诉我有没有新的 Rust edition 讨论"
astra jobs serve
```

`--time HH:MM` 按当地时钟在 `--days`（默认每天）运行，`--tz` 可指定 IANA 时区（默认本机），
夏令时切换后仍是同一个钟点。`--notify on_change` 时，检查会拿到上次已告诉用户的结果，
没有新内容就回 `NO_UPDATE`，这次记为安静结果。每次运行都会记录 token 用量。

对话里提出定时的事（“下午 3 点提醒我”“每天早上……”），Astra 可以用 `jobs` 工具建立和管理
同一份任务。新建、修改、恢复、删除、立即运行都会先请你批准（桌面或微信里都可以），
任务以你本人的那条消息作为授权；查看和暂停不需要批准。

Astra 桌面端开着（包括只留在托盘）时，它的后台进程负责运行到点的任务并推送结果：
桌面系统通知，以及发给扫码登录微信的那个人的微信消息。微信里的这条也会写进那个聊天的对话，
回复时她知道你指的是哪条。`--targets` 选择推送去处（默认 `desktop,weixin`，留空则只进收件箱），
所有结果都保留在收件箱。安静结果和错过时段的记录不推送。推送失败会在 1、5、15、30 分钟后重试，
之后放弃；运行开始超过 12 小时的结果不再推送。

检查结果和暂停通知会避开安静时段（默认 23:00–08:00，可用 `astra jobs quiet 开始 结束`
或 `astra jobs quiet off` 修改），你定了时间的提醒照常按时发。开了消息渠道，或者还有任务
可能运行、结果待推送时，桌面端会启动后台进程（任务库为此维护 `jobs/active`）。

桌面端侧栏的 **定时任务** 页面显示同样的任务、结果和安静时段，可以暂停、恢复、立即运行一次或删除。

不用桌面端时，在另一终端运行 `serve`，用 Ctrl+C 停止；不会自动安装系统服务。只要
这个进程仍在，GUI 重启不影响它。也可以让系统定时器周期调用 `astra jobs tick`。
所有调度器关闭期间，任务仍会保存；再次启动只在允许的补跑窗口内执行。

`--reminder` 直接投递文字，不调用模型；普通检查记录创建时选定的模型，
可以用 `--model KEY` 指定。普通检查必须填写原始用户授权 `--request`；
`--web` 才启用联网工具。每次检查使用独立的新会话，仅提供文件读取、
搜索和时间工具，没有 Shell、写文件、CU、子代理或外部渠道发送。

常用命令：`list`、`show JOB_ID`、`history JOB_ID`、`inbox`、
`inbox --read 执行ID`、`pause JOB_ID`、`resume JOB_ID`、`remove JOB_ID`。
`run JOB_ID` 是显式新建一次手动执行，不重放旧执行、不改变定期计划。
暂停或移除仅阻止未来调度，不终止已经运行的检查；记录会保留。

`--at` 必须包含时区，例如 `2026-10-06T09:00:00+08:00`。
`--every` 是固定秒数的间隔，不跟随夏令时；需要按当地时钟请用 `--time`。
`--catch-up` 限制迟到秒数：单次默认 300 秒，定期默认半个周期、最多一小时。
错过的区间会记为 `skipped`，至多补跑最近一次，不连续补跑历史任务。

任务也可以由事件而不是时间启动。`--on-mail-from 文字`、`--on-mail-subject 文字`（配合
`--on-mail-folder`，默认收件箱）在新邮件的发件人或标题包含该文字时启动；`--on-new-file 模式` 在
`--workdir` 里直接出现匹配的新文件（如 `'*.pdf'`）时启动。桌面端后台每五分钟看一次；第一次只记下当前
位置，已有的邮件和文件不会触发，每次每个任务最多启动五次。这样启动的提醒会附上邮件的发件人和标题或文件名；
检查会被告知是哪封邮件或哪个文件触发的（并且可以读邮件）。事件启动的任务的结果和检查结果一样避开安静时段。
对话里 `jobs` 工具的 `on_new_mail`、`on_new_file` 做同样的事。

任务会在两种情况下自动暂停，原因会进入收件箱：定期任务连续 3 次失败或结果未知；
桌面和消息渠道 7 天都没有收到你的消息时，定期任务暂停（一次性任务照常运行）。
恢复后从下一个时间点开始，暂停期间错过的不补跑。

`--idle` 是无活动超时（默认 120 秒），`--timeout` 是总时限（默认 900 秒），
`--iterations` 限制模型循环（默认 10 次）。崩溃或强制终止后不能确定结果的
执行会标记 `unknown`，不会自动重试。请先查看独立会话和记录，再决定是否
手动执行。结果入库和待投递记录一起提交，本地入箱和回执也一起提交，
重启不会重复入箱。`serve` 和 `tick` 只写入收件箱，推送由桌面端后台进程负责。

每个进程只服务一个 `ASTRA_HOME`，该目录下的 `.env` 若存在则用于任务。
模型、设置路径也应属于同一配置目录。技能格式互通及合并本轮不做。

检查模型仍在运行时，调度器会继续处理无需模型的提醒，避免提醒被慢请求阻塞。错过的时段以 `skipped` 写入本地收件箱；`list`、`show` 的 `last_outcome` 单独表示最近执行结果，不能把一次性日程的 `completed` 状态等同于执行成功。

中断执行时，调度器清理该 worker 所属的 POSIX 进程组或 Windows Job，并检查执行者的内核锁是否释放。若无法确认清理完成，本次执行继续保持占用状态，直到恢复流程确认执行者已退出；不会自动重放。POSIX 清理会先留出有限时间，让 worker 关闭其持有的独立 provider 进程。

更多参数和恢复规则见[英文说明](../persistent-jobs.md)。
