## 1. 目标与完成定义

最终目标：GUI 在相同平台、发行版、账号和权限条件下覆盖现有 Ink TUI 的全部用户能力，并以简洁、高效、可理解的界面呈现。中间阶段的聊天原型不能称为“GUI 已完成”。

- 采用用户提供的 Codex 截图作为布局参考：项目/会话侧栏、中心对话、底部输入、按需展开的工作面板。
- Electron + React DOM + TypeScript；复用 Astra Python 运行时、工具、记忆、Team 和持久化。
- 源码启动入口为 `astra --gui`；`astra` 继续提供默认终端入口。GUI 依赖准备纳入 `astra setup --gui`，后续更新纳入 `astra update`。
- GUI 与 TUI 使用同一安装的账号、配置、会话和产物；每台设备仍需分别登录。安装目录、数据目录与工作目录是三个不同概念。
- 模型自主选择工具和安排工作。GUI 的页面、任务分组和展示状态不成为模型必须遵守的工作流，不新增自动计划、强制评审、阶段锁或工具额度。
- 凡已在当前发行版 TUI 中可用的功能，均须有 GUI 内可发现、可完成的入口；低频功能可通过带参数表单的命令面板完成。不能以“回终端输入命令”作为完整覆盖。
- GUI 可以改进展现形式；终端 ANSI、字符边框和按键不要求逐像素复制。其背后的内容、操作、状态和可访问性必须保留。

“功能完整”的证据包括：附录 A 所有项目通过、动态命令及参数清单无遗漏、故障恢复场景通过，以及各发布平台独立验收。已有平台不支持的原生能力显示原因，不因 GUI 而宣称新增支持。dev 专用工具只在 dev 能力集合中出现。

桌面安装包、自动更新分发、移动端、远程多设备同步、语音、IDE 编辑器与 GitHub PR 产品面板不属于首次功能对等的必要条件；已有工具能执行的相关任务仍通过同一 agent 和结果视图使用。

## 2. 当前基础与需补齐的边界

现有入口：

| 源码 | 已有能力 | GUI 接入要求 |
| --- | --- | --- |
| `agent/launcher/{cli,installation,dependencies,update,locking}.py` | 安装识别、环境、锁定依赖、运行租约、恢复式更新 | GUI 成为可选组件，纳入检查、租约、构建与回滚 |
| `agent/cli/backend.py` | Python 主循环与逐行 JSON 命令/事件 | 分阶段提取界面无关的控制逻辑，保留兼容入口 |
| `ui-tui/src/types.ts` | PyEvent、TuiCommand、模式、模型、审批等类型 | 迁入共享协议包；补充会话路由与类型校验 |
| `ui-tui/src/backend-protocol.ts` | 事件去重、序列缺口和回放 | 分离纯协议处理与 Node 日志 I/O |
| `ui-tui/src/app.tsx` | 渲染、Python 进程启动、事件归约混合 | 只抽两种界面都需要的状态与控制，不搬运 Ink 组件 |
| `agent/runtime/event_stream.py`、`session_store.py` | 事件记录与会话存储 | 作为恢复事实来源，GUI 缓存不独立决定任务结果 |
| `agent/cli/turn_changes_command.py`、`agent/runtime/turn_change_store.py` | 只读回合变更账本 | 增加结构化查询，保留快照、缺失及粗略比较语义 |
| `ui-tui/src/appshot-*.ts`、`native/` | 捕获 broker、收件人、草稿与接收协议 | 新增 GUI 收件人适配，保持平台差异和单次接收约束 |

盘点发现 51 个顶层菜单命令，见附录 A。菜单不是唯一真相：后端参数、动态子菜单、本地快捷键与未列入菜单的兼容操作也属于验收范围。

关键缺口：

1. 部分流式事件缺少会话/请求关联字段；不能把来自不同后端的片段放进一个全局列表。
2. 历史快照与实时事件需要一致的消息身份和版本边界，避免恢复时重复、顺序倒置或旧快照覆盖新消息。
3. `/changes` 当前返回面向终端的文本；GUI 应查询同一个账本的结构化数据，不解析展示字符串作为数据源。
4. 多个界面共享会话文件，需要跨进程写入所有权，不能仅靠界面按钮禁用。
5. 模型登录成功、目录发现成功和实际推理成功是不同状态；GUI 分别呈现。

## 3. 信息架构与视觉设计

### 3.1 主布局

- 左栏默认 256 px，可折叠：新对话、搜索、置顶、项目及会话。底部提供设置入口和当前连接状态。
- 顶栏：会话标题、当前工作区、执行状态、详情开关。工作区始终可核对。
- 中心：对话正文，目标阅读宽度 760–960 px；表格、代码、图片和 diff 可横向展开。
- 底部：多行输入、附件、模型、推理强度、权限模式、发送/停止。低频操作进入更多菜单。
- 右栏默认关闭；打开时 360–520 px，可调整宽度。标签按需出现：文件、改动、工具/进程、Team、上下文。
- 小于 1100 px 时右栏改为覆盖抽屉；侧栏可折叠。1024×768 下主要操作无需水平滚动页面。
- 首次运行没有模型时，中心显示“连接模型”，包含 ChatGPT 登录和 API/本地模型选项。

颜色跟随系统浅色/深色，浅灰分区、细分隔线、有限强调色。Lyra 通过名称、文案与可选轻量主题表达。默认无持续动画。危险、失败、等待和成功不能只靠颜色区分。

### 3.2 渐进显示

对话正文、待回答问题和待处理审批优先；执行信息默认是一行可展开摘要。

- 工具卡片显示名称、状态、简短结果；原始参数、完整输出、耗时和产物在详情中。
- 多个并行工具合为一组，状态仍按 call_id 独立保留。失败与需要操作的条目保持可见。
- Team 默认显示正在工作的成员数与是否需要介入；展开后有成员、任务、消息和结果。
- 上下文、缓存、token 统计和速度进入上下文面板；以服务端实测口径展示，不估造未知值。
- 历史记录是主体；前端不把恢复出来的事件当作新消息或新通知。
- 错误与已有回复可以同时显示。收到部分正文后的失败，不删除已显示内容，也不标为完成。
- 推理可折叠；服务端只返回摘要时标记“推理摘要”，未返回时不生成替代内容。

### 3.3 键盘与输入

Enter 发送，Shift+Enter 换行；中文输入法 composition 期间 Enter 只确认输入。
Cmd/Ctrl+K 打开命令面板，输入框支持原有斜杠命令与补全。
Cmd/Ctrl+C 保持复制；停止使用明确按钮及 Cmd/Ctrl+.。终端 Ctrl+C 的取消/退出能力由这些入口等价提供。
工具详情和活动详情分别提供 Cmd/Ctrl+Shift+O、Cmd/Ctrl+Shift+L；权限切换可从命令面板调用，避免覆盖编辑器的重做快捷键。
Esc 关闭当前菜单/详情，不隐式取消正在执行的任务。问题、审批、模态框关闭后焦点回到来源控件。

附件可拖入、粘贴、选择、预览、移除。未发送草稿属于具体会话，不因切换会话或窗口重载丢失。
普通文件先作为有路径与元数据的附件交给后端既有读取能力；GUI 不自行把文件全文注入模型。图片沿用当前模型的视觉与预算规则。
剪贴板图像作为私有临时附件管理，未发送删除和过期清理可追踪。

### 3.4 首批必须设计的状态

空白/未连接、登录中、模型列表失败、正常对话、生成中、工具并行、待审批、待追问、
上下文压缩、取消中、部分失败、后端断开、恢复历史、文件 diff、Appshot 草稿、
特殊模式进入/退出、关闭窗口时仍有任务。每个状态都定义主操作、可撤销范围及错误后的下一步。

~~~mermaid
flowchart LR
~~~

### 4.1 模块职责

建议目录为 `ui-core/`（共享 TypeScript 包）、`ui-gui/`（Electron/React）、
`agent/ui/`（逐步提取的 Python 查询与命令服务）。三个目录已在源码预览版建立。

`ui-core` 提供事件/命令类型、运行时校验、去重/回放、会话状态归约、命令描述、选择器。
该包不依赖 Electron、Ink、DOM、Node fs 或 Python 进程；平台 I/O 通过适配器提供。
它有独立构建输出与 package exports，两个界面用本地 package 依赖引用，避免跨越现有 TypeScript rootDir 导入源码。
不为迁移而在仓库根建立无关的 npm 安装入口。

Electron main 管窗口、原生文件选择、受限产物访问、Appshot 收件人和 Python 进程。
preload 只暴露类型化功能；renderer 只管交互与显示。
Python 继续持有模型账号、业务配置、会话写入、工具权限、审批与执行语义。
GUI 的按钮、命令面板与斜杠命令最终进入相同后端服务，避免维护两套实现。

### 4.2 活跃会话与后台运行

一个 GUI host 管理当前安装/数据空间下的窗口与会话目录。每个活跃会话有独立后端、事件流、草稿和状态；
浏览历史列表不创建模型请求，也不为每条历史记录常驻 Python。

切换侧栏选中项只是切换视图，后台正在执行的会话继续运行。运行中、等待审批/追问、
存在 wakeup 或保留 Team worker 的后端不能因前端不可见被回收。
空闲且无这些状态的后端可由用户关闭，或按可配置的空闲策略释放；不更改模型轮次预算。

这与 TUI 在单个后端执行 `/session` 不同：GUI 切换视图不调用该命令来挪用活跃后端。
显式“切换此后端会话”仍遵守原命令的忙碌和 wakeup 终止语义。
相同会话不可被 TUI 与 GUI 同时作为写入者打开：在共享 Python 服务中获取
以数据根、模式命名空间和规范会话 ID 为键的跨进程所有权锁。
冲突时展示“另一实例正在使用”，允许只读查看或跳转已有 GUI 视图，不能静默抢占。

### 4.3 生命周期

- GUI 普通启动使用已构建资源，无需启动开发服务器；热更新为开发专用入口。
- `astra --gui` 启动托管 host，host 先取得安装运行租约；窗口握手成功后调用终端返回。
  host/Electron 与 Python 后端独立于调用终端生命周期。初期开发可先验证前台启动，但 G7 前须验收完整托管行为。
- 单实例键包含安装身份和数据空间；另一安装/配置不复用错误窗口。重复启动把规范工作区参数路由到已运行的 host。
- 后端重启只重建对应后端；renderer 重载从 host 状态快照及事件恢复，不重发用户请求。
- 关闭最后窗口且没有活动工作时正常退出；有工作/待处理交互/wakeup/保留 worker 时，
  提供“后台继续”“停止并退出”“返回”。后台继续有系统托盘/菜单入口。
- 真正退出时先按现有取消/停止语义收尾并保存，再释放子进程与租约；
  超时仍有不确定副作用时保留中断状态，不伪造成功。退出影响范围只限此 host 拥有的进程。
- 后端崩溃显示已断开与可恢复入口，遵守现有不自动重放不确定写操作的规则。

## 5. 协议、持久化与恢复

### 5.1 兼容扩展

保留现有逐行 JSON 传输和 `backend_hello.protocol_version`。
新增功能通过协商后的 capabilities 提供；不支持的后端显示具体版本/能力错误。
新字段向后兼容；改变必需字段或语义时升级协议并明确兼容范围。

GUI host 给每个通道绑定不可混淆的 `backend_instance_id` 与会话身份。
后端事件逐步补全 `session_id`、`request_id`、message/call/task ID；
生命周期沿用 event_id、generation、sequence、cursor。
请求确认、结果与错误均能关联请求。stdout 只传协议，诊断输出走日志或 stderr。

拟新增的查询能力：命令目录、会话分页与只读历史、运行状态快照、变更列表/diff、产物解析。
这些是服务能力名称，G0 冻结 wire schema 后再实现，不能由 renderer 直接读写 SQLite/JSONL。
列表、历史和产物读取是确定性的本地查询，不启动模型。

### 5.2 发送与恢复语义

- 用户提交使用唯一 submission_id；backend 接收确认与最终结束分开。
  普通消息/图片同样获得可查询的接收状态，沿用 Appshot 已有的防重复提交思路。
- 确认丢失先查询状态；对 unknown 显示不确定及人工处理选项，不自动再次执行原请求。
- 文本按 message_id 和增量偏移归约；同一片段重复或跨重启到达不能拼接两次。
- history 是带 revision/cursor 的快照，不是向旧列表追加。
  活跃回复片段在 host 中有可重建缓冲；先取快照，应用晚于边界的事件。
  已结束正文与持久化历史一致，恢复过程不替换用户草稿。
- 现有持久化日志未承诺保存每个 volatile 文本帧：跨 host 崩溃只能恢复已持久化内容，
  缺口显示“输出中断”，不能声称所有屏幕片段都已保存。
- 审批/追问按 request_id 处理，只在后台确认后进入最终状态。
  回放不得复活已经答复、取消或失去宿主的控件。
- 受控重启沿用 restart_ready → 前端应用/呈现完成 → restart_ack。
  仅 JSON 解析成功不能当作已向用户呈现；超时沿用现有取消重启行为。
- 流式刷新可以合并相邻文字更新，但不丢弃错误、审批、任务结束、控制权和变更账本事件。

### 5.3 数据归属

沿用 `ASTRA_HOME`、`AGENT_SESSION_DIR` 以及 launcher 的实际安装身份；
默认源安装使用既有 `.astra/` 和 `.sessions/`，不建立另一套 GUI 历史。

GUI 私有界面偏好存放在当前 state 下的 `gui/`：窗口位置、侧栏宽度、置顶与项目分组、
草稿、最近查看位置。界面缓存可重建；项目元数据是新增 GUI 展示能力，
不等于改变已有会话的工作区或把多个项目文件注入上下文。
首次导入现有会话时，无法证实工作区的记录标为“未关联”，由用户选择，不依据标题猜测。

只读历史浏览不能触发 SessionStore 的恢复写入；任何 schema 迁移、rename/delete/export
经过 Python 服务，并覆盖隔离模式对应的命名空间和侧文件。

多个后端共享 settings、提供商配置和认证数据时，由共用存储服务执行原子写入与跨进程协调；
同一账号的 token 刷新也需串行，不能由各窗口覆盖彼此的新凭证。
配置变更带修订号通知相关后端；区分当前会话选择、启动默认值和正在执行请求的配置快照，
不能因为另一会话修改默认模型而切换已发出的请求。权限和 YOLO 沿用现有作用域，
一次性审批不能扩散到其他会话。GUI 展示变更的生效范围及是否需要重连。

| 拟定命令 | 行为 |

优先在 macOS 和 Windows 验收；Linux 源码 GUI 覆盖其现有 TUI 可用的通用功能，单独记录验证结果。

完整安装包后续再规划 Python/辅助程序打包、签名、公证与更新渠道；不改变当前数据归属约定。

## 7. 关键功能的展现与语义

### 7.1 账号与模型

提供清晰的未连接、授权中、已保存凭证、目录加载中、目录失败、已选模型状态。
授权页展示可信 URL、代码、倒计时和取消；Key 字段遮蔽、不入对话/诊断。
保留地域/API/订阅路线，手动 ID、模型目录刷新、live/cache/stale/preset 来源与目录错误。
选中模型不宣称推理已验证；连接错误不静默切换收费路线。
“每台电脑单独登录”出现在首次引导与故障提示中。

### 7.2 工具、审批、Team 与后台进程

模型输出、工具派发、执行完成和持久化是不同状态。保留 call_id 与任务归属，避免“回复已结束但仍显示 RUN”。
用户可查看完整参数/输出与文件结果，错误保留 code、partial、retryable、dispatch_state、recovery_hint。
展示出的“重试”必须由后端判定可重试或走原有显式用户重试语义，不能重放已经产生不确定外部效果的工具调用。

审批呈现实际作用域和 once/session/deny 选择，实时同步 YOLO 变化。
追问支持单选、多选、自由文本、取消及后台拒绝原因；等待输入时其他任务仍可浏览。
Team 页展示已创建成员和真实 idle/running/terminal 状态。提供已有工具支持的发送、查看与停止操作；
新按钮调用同一授权服务，不引入第二套 agent 管理器。
进程输出按块读取，工具结果截断不等于文件/日志丢失。

### 7.3 文件、图片与变更

变更视图读取已封存回合账本：回合、路径、增加/删除行数、前后快照、不可捕获/淘汰/二进制/粗略比较说明。
首次 GUI 提供查看、复制路径、打开产物；现有账本是只读能力，不能凭“有 diff”承诺一键回滚。
大文件分块/分页，图片按可见区域懒加载；原文件与快照分开标记。
工具产物可在支持的预览器打开；不支持的格式提供系统打开/保存入口。
终端输出首先提供只读日志视图，交互式终端不是覆盖现有日志查看的前置条件。

### 7.4 Appshot 与 Computer Use

GUI 收件人按真实输入活跃度与会话身份注册 broker；前台窗口检查、快捷键与 native helper 保留平台适配。
捕获进入正确会话草稿，允许预览/移除；发送是独立用户动作。
busy、pending、unknown、discard 与四项附件上限沿用现有协议；
点击 GUI 接收按钮和 broker 重传不能造成重复模型请求。
电脑控制的 background/foreground_takeover/user_control/paused 和 degraded 状态保持可见，并提供停止/设置入口。
不自动夺取用户前台窗口或因页面切换重新获取浏览器控制。

### 7.5 模式、记忆、技能与会话内提醒

Work/Minimal/Bar 与已安装的本地模式 使用各自控制器和存储空间，进入/退出准确恢复原上下文。
GUI 页签不把隔离会话内容混入 Work，也不改变现有模式的工具/记忆/学习规则。
Bar 保留状态、手动动作及 atomic/stream 的完成语义，采用简洁专属视图。
记忆与技能面板显示现有证据、来源、变更和撤销结果；对话式命令仍由既有服务运行。
wakeup 明示“此会话后端在线时有效”；单纯切换 GUI 视图可继续，
真正切换后端会话/重启/退出按现有语义停止。不得包装成离线持久定时服务。

## 8. 本地内容与进程边界

Electron renderer 使用 contextIsolation、sandbox，关闭 nodeIntegration；
preload 暴露窄接口，main 校验 sender、数据结构、会话归属与权限。
Markdown/工具输出/网页内容均视为展示数据，禁用主动脚本与任意 IPC。
外部链接仅在用户操作后交给系统浏览器；OAuth 登录不加载到有特权的应用页面。

通过产物引用、用户文件选择或已有授权路径打开本地文件。
main/后端校验规范路径、符号链接、作用域、大小与 MIME；renderer 不获得任意 fs/shell 接口。
凭证只在原有认证组件中持久化，日志脱敏；选中 Key 不进入分析事件或剪贴板自动操作。
这些边界保护桌面应用，不额外限制模型已获得授权的工具能力。

## 9. 简洁、高效与验收指标

以下为最终验收目标；当前夹具只提供部分测量，不能视为全部达标。基准用独立空闲机器运行，记录系统/CPU/RAM/显示缩放、commit、
Electron/Node/Python 版本和数据集。模型网络耗时与 Python 模型初始化单独报告。

| 项目 | 目标 |
| --- | --- |
| GUI 初始窗口 | 已安装构建的冷启动 p95 ≤ 3 秒；后端未就绪时窗口可响应并显示阶段 |
| 普通交互 | 输入回显、打开菜单/切换详情 p95 ≤ 100 ms |
| 大历史 | 10,000 条消息/20 MiB 文本夹具，首屏 p95 ≤ 1 秒，历史分页与虚拟化，不一次挂载全量 DOM |
| 流式输出 | 150 tokens/s 等价文本流持续 10 分钟，输入 p95 ≤ 100 ms，事件无缺失/重复；界面文字刷新合并窗口 ≤ 50 ms |
| 后台压力 | 3 个活跃会话、每个 100 工具事件/秒的夹具下，审批/取消状态可响应；大输出落盘并按需读取 |
| 内存 | 上述历史夹具稳态相对空白窗口增量 ≤ 250 MiB（host/main/renderer，排除 Python 和系统 GPU），30 次会话切换后无持续线性增长 |
| 可达性 | 发送/停止直接可见；模型/权限/附件至多两步；低频功能可在命令面板检索并在 GUI 完成 |
| 可访问性 | 完整键盘操作、可见焦点、中文 IME、200% 缩放、减少动画、读屏标签；文字对比度以 WCAG AA 为设计目标 |
| 恢复正确性 | 历史与当前会话不串线；重复/丢失/迟到事件夹具不重复执行；未知副作用如实显示 |

如果某平台不达标，提交具体测量、瓶颈和修复结果；不能以平均值掩盖尾部卡顿。
渲染性能优化不得降低会话完整性或丢弃重要事件。

功能对等按当前能力清单持续更新，而非永远固定在这 51 个命令。
